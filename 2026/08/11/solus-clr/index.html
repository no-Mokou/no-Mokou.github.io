Solus Linux系统引导管理器二三事

发表于2026-08-11|更新于2026-08-11
|总字数:2.2k|阅读时长:7分钟|浏览量:

教你如何在Solus Linux里正确的切换内核版本，避免踩坑

前言

前文我说到过我比较小众，连使用的Linux系统都如此小众，它就是名不见经传的Solus Linux，说白了在国内挺非主流的。至于用Linux的原因就是体积小，速度快，资源占用小，方便调试。对于从事Android开发的我及我那可伶性能的轻薄本来说都是优势。(OS: 主要是内存金贵买不起🤑)

众所周知Solus的引导管理器为clr-boot-manager，最早被用于Intel旗下的Clear Linux，而因为Intel的刀法大家都清楚嘛，Clear Linux已荣光不再，自然而然这个年轻的引导管理器之重任就压在了Solus之上，Solus作为当今clr-boot-manager的主要开发维护者和使用者，背负着它迷茫的前行。

本文主要讲如何升级内核，降级的话类似。因为我曾经踩过几次切换内核的坑，后果有：

  1. 要么被迫重装。（因为输错命令导致新旧内核一并丢失）
  2. 要么能进桌面，但所有驱动完全失效，只能干看着桌面。（我的台式机就这样了，还好笔记本严格遵守了切换流程）
  3. 要不就是图形化桌面直接没有了，需要用到当初安装时所需的Live系统介入修复，非常繁琐。

可以见得，真的不要随随便便就清理旧内核，以上事件就发生在清理过程上。那为什么要清理呢？因为不清理的话EFI就爆掉了，没法完成升级，这也许是双系统的痛，我的系统环境是Windows/Linux双修 (传统双系统)，EFI占用大，就只能走清理这条路啦。

接下来本文将完整带你走一遍内核切换、清理、回滚的全流程，核心操作步骤整理如下表 (install实际可以简写为it)：

核心操作一览表

步骤 操作目的 命令 注意事项
1 查看当前内核版本 uname -r 记住这个版本号，后面清理时别删错
2 列出所有已安装内核 sudo clr-boot-manager list-kernels 输出示例：linux-current-7.1.7-351、linux-lts-7.1.5-349
3 切换到LTS内核 sudo clr-boot-manager set-kernel linux-lts && sudo clr-boot-manager update ⚠️ 执行后必须重启才生效
4 切换回current内核 sudo clr-boot-manager set-kernel linux-current && sudo clr-boot-manager update ⚠️ 执行后必须重启才生效
5 安装LTS内核（如未安装） sudo eopkg install linux-lts 安装后执行步骤3进行切换
6 临时选择内核启动 重启时按 空格键 进入GRUB菜单手动选择 不改变默认内核，仅供临时测试
7 删除指定内核（正确姿势） sudo clr-boot-manager remove-kernel com.solus-project.current.7.1.5-349 ✅ 必须指定完整版本号
8 删除所有同名内核（危险操作） sudo clr-boot-manager remove-kernel linux-current ❌ 严禁执行！会删掉正在使用的内核
9 查看/boot分区剩余空间 df -h /boot 一定要保留部分可用空间
10 搜索可安装的内核版本 eopkg search linux-current 用于查找特定旧版本号
11 重启系统 sudo reboot 切换内核后必须执行
12 验证切换结果 uname -r 重启后执行，确认版本已改变

重点说明

❓ 为什么升内核

主要是考虑到新功能及修复，我比较“追新”，这是其一，其二是最近大家都看到了，Linux内核漏洞被AI爆出来很多，升级是为了规避风险，当然了你也可以选择不升，固步自封。没有什么特殊要求的话是建议升级的，希望这篇文章迟早能帮助到同样“小众”的你，以current版本为例。

保险起见升内核流程应当是以下两种方法选一种

  1. Discover 软件中心 -> 更新 (适用于大多数人和大多数情况，很方便)

  2. 传统命令方式，建议是所有组件干脆一起升级，因为真的可能会有升了内核然后组件出bug或者升了组件然后内核不适配组件的bug，执行sudo eopkg up (upgrade实际可以简写为up)。除非你有强制需求否则不建议手动去安装指定内核。

希望看完核心操作的你不要着急输入命令，我梳理过了更通俗易懂的流程 (上面那个是AI梳理的噢😄)

  1. 第一步打开你喜欢的任何终端都行，默认你已经下载完了新版内核。

  2. 输入sudo clr-boot-manager list-kernels，此时会看见你下载好的新内核及打着*号 (星号)的旧内核，也就是你正在使用的内核，当然，可能你从来不清理就会同时看到多个内核版本，选好最新的即可。

  3. 输入sudo clr-boot-manager set-kernel <kernel-version>，注意，这里的<kernel-version>指的是带com.solus-project.current.x.x.x-xxx的完整version，千万不要直接输入数字version，如7.1.7-351，真的是血泪教训，当初我第一次切内核就犯了这个大忌，当时因为和清理一并执行，新旧内核都没了，被迫重装。正确范例：sudo clr-boot-manager set-kernel com.solus-project.current.7.1.7-351 (嫌长的话复制粘贴不用我教吧…)

  4. 现在可以选择检查*号 (星号)是否在你所切换的内核之前了，也可以不检查，直接下一步，如果你的EFI大小充足，可以直接执行sudo clr-boot-manager update，如果你的EFI大小并不充裕，应先清理旧内核，执行sudo clr-boot-manager remove-kernel <kernel-version>，和set-kernel同理，版本号一定要复制完整，再执行sudo usysconf run -f，二者皆是等待完毕后重启。

5. 保险起见重启后可再直接执行一次sudo clr-boot-manager update，当然这不是必要的，而是怕系统万一存在什么bug。

⚠️ 清理内核注意

Solus 的 EFI 分区官方要求是 512MB，但像我这样持有双系统的在分区上做不到，除非你是只有这一个系统，那升级时估计自动切换新版了，这篇文章对你帮助就不大。而内核装多了 EFI 分区必然会爆满，直接导致系统更新失败。如果你跟我情况一样，务必定期清理旧内核。

正确的清理方式：最好是一条一条的删，避免错删误删。
挨条执行sudo clr-boot-manager remove-kernel com.solus-project.current.x.x.x-xxx，按具体版本号具体行事，一定要看清楚了再删哦。搞清楚命令是死的，人是活的哟。

🔴 我的翻车案例

我第一次用Solus Linux的时候得追溯到2024年，当时还是Solus 4.5，当时这个系统还有点毛坯房的感觉，很多东西不太完善，而且能查到的资料又少，导致在当时本就不大熟悉Linux的我应付这些问题更是雪上加霜。梳理了下我2024-2026年间遇到的切换内核问题包括但不限于 (排序不分先后)：

  1. 脑子一热输入了sudo clr-boot-manager set-kernel current.x.x.x-xxx，或sudo clr-boot-manager set-kernel x.x.x-xxx，这种无效切换，我都不记得当时自己怎么想的。。本来这也没啥事，坏在后面直接把内核删了，当时删除复制了完整的而设置却没有，重启就出事。真是气死我了呀！

  2. 执行remove-kernel相关时不慎把所有内核全删了，包括正在运行的，神奇的是你不重启它看不出来毛病，一重启就毁了。

  3. 正常执行切换流程，但是有一个自动切换包流程出了个什么错误，没在意，完事重启后遇上了我前面写到的踩坑第二条，我怀疑当时真的是系统bug，只能说多留个心眼吧。

  4. 也就是前面的踩坑第三条，好像是官方编译的内核出了问题，然后后面绕了很多弯子去修复它。

  5. EFI爆了，只遇到过一次，具体影响就是使用体验相当奇怪，各种桌面，窗口bug都冒出来。

所以删除内核请务必指定完整版本号进行删除！！！

结语

希望屏幕前的你不要重蹈我的覆辙，真的麻了。
